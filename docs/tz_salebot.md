# Техническое задание

## Telegram-бот стоматологии «Голден Дент» на платформе salebot.pro

Документ описывает функциональность Telegram-бота, разрабатываемого на платформе salebot.pro без интеграций с внешними системами (Google Sheets, CRM). Все данные клиентов и контента хранятся в нативных объектах salebot: переменных клиента, глобальных переменных и списках. Рассылки выполняются Заказчиком через встроенный конструктор рассылок salebot.pro.

---

## 1. Общие сведения

| Параметр | Значение |
|---|---|
| Платформа | salebot.pro (рекомендуемый тариф — «Стандарт» или выше) |
| Канал | Telegram (один Telegram-бот, токен предоставляет Заказчик) |
| Часовой пояс | Asia/Novosibirsk (UTC+7) — задаётся в настройках кабинета salebot |
| Язык интерфейса | Русский |

**Цель бота:** автоматизировать коммуникации стоматологии с пациентами между визитами — регистрация, напоминания о записях, периодические напоминания о профосмотре, поздравления с днём рождения, презентация спецпредложений.

## 2. Структура данных в salebot

### 2.1. Переменные клиента (индивидуальные для каждого пользователя)

| Имя переменной | Тип | Назначение | Кто заполняет |
|---|---|---|---|
| `consent_given_at` | дата+время | Время согласия на обработку ПДн | Бот при нажатии «Продолжить» |
| `fio` | строка | ФИО клиента | Бот при регистрации |
| `phone` | строка | Номер телефона | Бот при регистрации |
| `birth_date` | дата (ДД.ММ.ГГГГ) | Дата рождения | Бот при регистрации |
| `tg_username` | строка | Telegram-username (системная) | Salebot автоматически |
| `tg_user_id` | число | Telegram user id (системная) | Salebot автоматически |
| `last_visit_date` | дата | Дата последнего визита в клинику | Заказчик через CSV-импорт |
| `appointment_date` | дата+время | Дата и время ближайшей записи | Заказчик через CSV-импорт |
| `appointment_status` | строка | подтверждено / отменено / перенос / не готов | Бот по нажатию кнопки |
| `appointment_cancel_reason` | строка | Причина отмены записи | Бот при выборе причины |
| `not_ready_comment` | строка | Комментарий клиента при отказе | Бот при сборе комментария |
| `last_remind_status` | строка | Статус последнего касания | Бот |

### 2.2. Глобальные переменные (общие для всего бота)

| Имя переменной | Назначение |
|---|---|
| `clinic_name` | Название клиники для подстановки в сообщения |
| `birthday_bonus_amount` | Сумма подарочного сертификата на день рождения (например, `1000`) |
| `admin_book_url` | Telegram-ссылка на администратора с предзаполненным текстом «Хочу записаться» |
| `admin_contact_url` | Telegram-ссылка на администратора для общих вопросов |
| `admin_birthday_url` | Telegram-ссылка для активации подарочного сертификата |
| `consent_policy_url` | Ссылка на политику обработки ПДн |
| `consent_rules_url` | Ссылка на правила использования бота |
| `start_text` | Текст приветствия в главном меню |
| `start_image` | Фото клиники для главного меню |
| `about_text` | Текст раздела «О нас» |
| `about_image` | Фото для раздела «О нас» |
| `special_offers_header` | Заголовок раздела спецпредложений |

Для каждой акции — отдельный набор переменных:
`offer_<N>_title`, `offer_<N>_text`, `offer_<N>_image`, `offer_<N>_book_url`, `offer_<N>_buy_url` (где N = 1..5).

### 2.3. Списки

| Список | Назначение | Поля |
|---|---|---|
| `Не готов записаться` | Журнал отказов с комментариями (для аналитики Заказчика) | дата, tg_username, fio, phone, комментарий |
| `Отмены записи` | Журнал отмен с причинами | дата, tg_username, fio, phone, дата записи, причина |
| `Не доставлено` | Пациенты, которым не дошло сообщение | дата, tg_username, тип сообщения (appointment / 3m / 6m / birthday) |

### 2.4. Теги клиентов

| Тег | Когда ставится | Когда снимается |
|---|---|---|
| `consent_given` | После согласия на обработку ПДн | — |
| `registered` | После заполнения ФИО, телефона, даты рождения | — |
| `appointment_tomorrow` | Если `appointment_date` = завтра | После прохождения дня записи |
| `birthday_today` | Если день и месяц `birth_date` = сегодня | Через 1 день |
| `remind_3m_due` | Если `last_visit_date + 3 мес` = сегодня | Через 1 день |
| `remind_6m_due` | Если `last_visit_date + 6 мес` = сегодня | Через 1 день |

## 3. Сценарии бота

### 3.1. Сценарий «Старт» (онбординг)

**Триггер:** команда `/start`, кнопка «Начать».

**Логика (блок-схема):**

1. Проверка переменной `consent_given_at`:
   - если задана → переход на сценарий «Главное меню» (3.2);
   - если пуста → шаг 2.
2. Сообщение с текстом согласия на обработку ПДн и тремя кнопками:
   - «✔ Продолжить» → шаг 3;
   - «Политика обработки ПДн» — URL-кнопка на `consent_policy_url`;
   - «Правила использования бота» — URL-кнопка на `consent_rules_url`.
3. По нажатию «Продолжить»:
   - записать `consent_given_at = текущее время`;
   - поставить тег `consent_given`;
   - перейти на регистрацию (шаг 4).
4. Запросить ФИО (текстовый ввод, валидация — не пусто) → записать в `fio`.
5. Запросить телефон:
   - кнопка «Поделиться контактом» (Telegram contact request) → записать `phone`;
   - либо ручной ввод (валидация — содержит цифры, длина 10–15) → записать `phone`.
6. Запросить дату рождения (текстовый ввод, формат ДД.ММ.ГГГГ, валидация даты) → записать в `birth_date`.
7. Поставить тег `registered`.
8. Поставить отложенное действие «через 3 дня» → запустить сценарий «Касание через 3 дня» (3.5).
9. Перейти на сценарий «Главное меню» (3.2).

### 3.2. Сценарий «Главное меню»

**Триггеры:** команда `/menu`, кнопка «В начало», завершение регистрации, повторный `/start` после согласия.

**Сообщение:** фото `start_image` + текст `start_text`.

**Inline-кнопки:**
- «Записаться на приём» — URL-кнопка на `admin_book_url`;
- «О нас» → сценарий «О нас» (3.3);
- «Спецпредложения» → сценарий «Спецпредложения» (3.4);
- «Связаться с администратором» — URL-кнопка на `admin_contact_url`.

### 3.3. Сценарий «О нас»

**Сообщение:** фото `about_image` + текст `about_text`.
**Кнопка:** «В начало» → сценарий «Главное меню» (3.2).

### 3.4. Сценарий «Спецпредложения»

**Сообщение:** заголовок `special_offers_header`.
**Inline-кнопки** (по умолчанию пять, по числу акций):
- «Взрослый абонемент» → блок акции 1;
- «Детский абонемент» → блок акции 2;
- «Имплантация + коронка» → блок акции 3;
- «Удаление зубов ультразвуком» → блок акции 4;
- «Отбеливание FLASH» → блок акции 5.

**Блок отдельной акции (повторяется для каждой):**
- сообщение: фото `offer_<N>_image` + текст `offer_<N>_text`;
- кнопки:
  - «Записаться» — URL-кнопка на `offer_<N>_book_url`;
  - «Купить абонемент» — URL-кнопка на `offer_<N>_buy_url` (показывать только если переменная заполнена);
  - «В начало» → сценарий «Главное меню» (3.2).

### 3.5. Сценарий «Касание через 3 дня»

**Триггер:** отложенное действие из сценария «Старт» (3.1, шаг 8).

**Условие запуска:** клиент не записался за прошедшие 3 дня (переменная `appointment_date` пуста или в прошлом).

**Сообщение:**
> Здравствуйте! Готовы записаться на приём?

**Inline-кнопки:**
- «Записаться сейчас» — URL-кнопка на `admin_book_url`;
- «Напомните через 2 недели» → сценарий 3.6;
- «Не готов записаться» → сценарий 3.7.

### 3.6. Сценарий «Напомните через 2 недели»

1. Сообщение: «Хорошо, вернёмся через 2 недели. Хорошего дня!».
2. Записать `last_remind_status = "напомнить через 2 недели"`.
3. Поставить отложенное действие «через 14 дней» → отправить то же сообщение из 3.5 с теми же тремя кнопками.

### 3.7. Сценарий «Не готов записаться»

1. Сообщение: «Подскажите, пожалуйста, почему не получается?».
2. Ожидание текстового ввода → записать в `not_ready_comment`.
3. Добавить элемент в список `Не готов записаться`: дата+время, `tg_username`, `fio`, `phone`, `not_ready_comment`.
4. Записать `last_remind_status = "не готов"`.
5. Сообщение: «Спасибо! Мы учтём ваш ответ.».

### 3.8. Сценарий «Напоминание о записи на завтра»

**Триггер:** ежедневная рассылка в 12:00 по аудитории с тегом `appointment_tomorrow` (тег ставится автоматически при ежедневной проверке: `appointment_date - сегодня = 1 день`).

**Сообщение:**
> Здравствуйте, [fio]! Напоминаем о вашей записи [appointment_date] в клинику «[clinic_name]».

**Inline-кнопки:**
- «✔ Подтверждаю» → записать `appointment_status = "подтвердил"`, сообщение «Отлично, будем ждать!»;
- «✖ Отменить» → подсценарий 3.8.1;
- «🔁 Перенести запись» — URL-кнопка на `admin_book_url`.

#### 3.8.1. Подсценарий «Отмена записи»

1. Записать `appointment_status = "отменил"`.
2. Сообщение «Уточните, пожалуйста, причину отмены:» с четырьмя кнопками:
   - «1. Изменились планы»;
   - «2. Неактуально»;
   - «3. Заболел»;
   - «4. Другое».
3. По нажатию 1–3:
   - записать `appointment_cancel_reason = текст кнопки`;
   - добавить элемент в список `Отмены записи`;
   - сообщение «Спасибо, отметили отмену записи».
4. По нажатию «Другое»:
   - запросить причину в свободной форме;
   - записать в `appointment_cancel_reason`;
   - добавить элемент в список `Отмены записи`;
   - сообщение «Спасибо, отметили отмену записи».

### 3.9. Сценарий «Напоминание через 3 месяца»

**Триггер:** ежедневная рассылка в 12:00 по аудитории с тегом `remind_3m_due` (тег ставится при условии `last_visit_date + 3 месяца = сегодня`).

**Сообщение:**
> Здравствуйте, [fio]! С момента вашего последнего визита в «[clinic_name]» прошло 3 месяца — рекомендуем профессиональную гигиену и осмотр.

**Inline-кнопки:** те же три, что в сценарии 3.5.

### 3.10. Сценарий «Напоминание через 6 месяцев»

**Триггер:** ежедневная рассылка в 12:00 по аудитории с тегом `remind_6m_due` (`last_visit_date + 6 месяцев = сегодня`).

**Сообщение:**
> Здравствуйте, [fio]! С момента вашего последнего визита прошло 6 месяцев — это оптимальное время для профилактического осмотра.

**Inline-кнопки:** те же три, что в сценарии 3.5.

### 3.11. Сценарий «Поздравление с днём рождения»

**Триггер:** ежедневная рассылка в 12:00 по аудитории с тегом `birthday_today` (день и месяц `birth_date` = сегодня).

**Сообщение:**
> 🎉 [fio], с днём рождения! От клиники «[clinic_name]» дарим вам подарочный сертификат на [birthday_bonus_amount] руб. на любые услуги.

**Кнопка:** «🎁 Использовать сертификат» — URL-кнопка на `admin_birthday_url`.

### 3.12. Обработка недоставленных сообщений

В сценариях 3.5, 3.8, 3.9, 3.10, 3.11 после блока отправки добавить ветку «при ошибке доставки» → добавить элемент в список `Не доставлено`: дата+время, `tg_username`, тип сообщения.

## 4. Импорт и обновление данных

### 4.1. Первичный импорт базы клиентов

Заказчик готовит CSV/Excel-файл со столбцами:
`tg_username`, `fio`, `phone`, `birth_date` (ДД.ММ.ГГГГ), `last_visit_date` (ДД.ММ.ГГГГ).

Исполнитель импортирует файл через встроенный механизм импорта пользователей salebot.pro.

**Важное ограничение Telegram:** бот не может писать первым пользователю, который не запускал бота через `/start`. Импортированные клиенты получат данные в кабинете, но автоматические напоминания будут уходить только тем, кто хотя бы раз запустил бота.

### 4.2. Обновление дат записи

В конце каждого рабочего дня Заказчик готовит CSV-файл со столбцами:
`tg_username`, `appointment_date` (ДД.ММ.ГГГГ ЧЧ:ММ).

Импорт обновляет переменную `appointment_date` у соответствующих клиентов. Тег `appointment_tomorrow` ставится автоматически при проверке.

### 4.3. Обновление даты последнего визита

При завершении приёма пациента Заказчик обновляет `last_visit_date`:
- через CSV-импорт (массово, в конце дня);
- либо вручную в карточке клиента в кабинете salebot (точечно).

## 5. Рассылки

5.1. Кастомные массовые рассылки выполняются Заказчиком самостоятельно через встроенный конструктор рассылок salebot.pro.

5.2. Исполнитель проводит обучение по работе с конструктором рассылок (1 онлайн-встреча, до 60 минут):
- выбор аудитории (по тегам, по списку, по фильтрам);
- составление сообщения с фото и кнопками;
- запуск с предварительным просмотром и подтверждением;
- просмотр статистики доставки;
- работа со списком `Не доставлено` после рассылки.

## 6. Администрирование контента

6.1. Тексты, фото и URL-кнопки спецпредложений, текст и фото главного меню, текст «О нас», сумма сертификата на день рождения, ссылки на администратора — всё хранится в глобальных переменных salebot.pro и доступно для редактирования через интерфейс кабинета.

6.2. Изменения в глобальных переменных вступают в силу немедленно после сохранения, без участия Исполнителя и без перезапуска бота.

6.3. Добавить новых сотрудников в кабинет salebot.pro Заказчик может самостоятельно (при наличии тарифа, поддерживающего нескольких пользователей).

## 8. Что не входит в ТЗ

- Интеграция с Google Sheets, CRM-системами, медицинскими программами учёта.
- Разработка кастомной админ-панели вне salebot.pro.
- Хостинг и оплата подписки salebot.pro (выполняется Заказчиком).
- Дизайн фирменного стиля, иллюстрации, копирайтинг (тексты и фото предоставляет Заказчик).
- Подключение каналов помимо Telegram (WhatsApp, VK, Авито, Instagram).
- Голосовые ассистенты, AI-ассистенты, генеративный контент.
- Перенос исторических переписок и данных из старого бота (если он использовался).

## 10. Чек-лист тест-кейсов для приёмки

1. `/start` от нового пользователя → запрашивается согласие → ФИО → телефон → дата рождения → главное меню.
2. `/start` от уже зарегистрированного пользователя → сразу главное меню без повторной регистрации.
3. Кнопка «О нас» → сообщение с фото и кнопкой «В начало».
4. Кнопка «Спецпредложения» → меню из 5 акций → переход в каждую → возврат «В начало».
5. Через 3 дня после регистрации (или по тестовому триггеру) приходит сообщение с тремя кнопками.
6. «Напомните через 2 недели» → подтверждение → проверка, что через 14 дней приходит повторное сообщение.
7. «Не готов записаться» → ввод комментария → запись попадает в список «Не готов записаться».
8. Установить `appointment_date` на завтра → в 12:00 приходит напоминание о записи.
9. «Подтверждаю» в напоминании → переменная `appointment_status` обновляется.
