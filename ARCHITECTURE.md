# Архитектура Telegram-бота «Голден Дент»

Документ для заказчика. Описывает путь клиента в боте и функциональные возможности для администрации клиники.

---

## 1. Что умеет бот в двух словах

Бот — это точка касания с пациентом между визитами: собирает согласие и контакты, показывает спецпредложения, автоматически напоминает о визите на завтра и о плановых осмотрах через 3 и 6 месяцев, поздравляет с днём рождения и выдаёт сертификат. Для клиники — удобная панель редактирования контента, кастомные рассылки и полная синхронизация с Google Sheets.

---

## 2. Путь клиента

### Шаг 1. Первый запуск `/start`
1. Бот показывает **экран согласия на обработку персональных данных** с кнопками:
   - «✔ Продолжить»
   - «Политика обработки ПДн» (PDF или внешняя ссылка)
   - «Правила использования бота»
2. Пациент соглашается → бот запрашивает **ФИО**.
3. Затем запрашивает **телефон** (кнопкой «Поделиться контактом» или текстом).
4. Затем запрашивает **дату рождения**.
5. Все данные сохраняются: `tg_username`, ФИО, телефон, дата рождения, `user_id`, время согласия. Попадают в Google Sheets → лист **«БД - клиенты»**.

### Шаг 2. Приветственный экран
После регистрации бот отправляет **фото клиники (`logo-gd.jpg`) + приветственный текст** и меню из 4 кнопок:
- **Записаться на приём** → открывает диалог с администратором в Telegram с готовым текстом.
- **О нас** → краткое описание клиники (+ фото).
- **Спец предложения** → подменю с актуальными акциями.
- **Связаться с администратором** → диалог с админом в Telegram.

### Шаг 3. Спецпредложения
В подменю акций по умолчанию пять позиций (всё редактируется админом из бота):
- Взрослый абонемент на 4 чистки
- Детский абонемент на 4 чистки
- Имплантация + коронка
- Удаление зубов ультразвуком
- Отбеливание «FLASH»

Каждая акция = фото + описание + кнопки «Записаться» / «Купить абонемент» / «В начало».

### Шаг 4. Через 3 дня после `/start`
Автоматическое касание: отдельное сообщение с тремя кнопками:
- **Записаться сейчас** → переход к администратору.
- **Напомните через 2 недели** → бот ставит отложенную задачу на 14 дней и вежливо прощается.
- **Не готов записаться** → бот просит причину, клиент пишет комментарий → сообщение попадает в лист **«Не готов записаться (комментарии)»** (дата, username, текст, ФИО, телефон).

### Шаг 5. Напоминания по расписанию (ежедневно в 12:00 по Новосибирску)

**A. Запись на завтра.** Если в таблице стоит запись на завтрашний день, клиенту приходит напоминание с тремя кнопками:
- **Подтверждаю** → статус «подтвердил» в таблицу.
- **Отменить** → бот спрашивает причину (4 варианта: Изменились планы / Неактуально / Заболел / Другое с вводом своего текста) → статус и причина сохраняются в таблицу.
- **Перенести** → открывает чат с администратором для переноса.

**B. Напоминание через 3 месяца после визита.** Автоматически, если «дата последнего визита + 3 месяца = сегодня».

**C. Напоминание через 6 месяцев после визита.** Аналогично, если «дата + 6 месяцев = сегодня».

Во всех напоминаниях доступны те же 3 кнопки: «Записаться сейчас» / «Напомните через 2 недели» / «Не готов записаться».

### Шаг 6. Поздравление с днём рождения
В день рождения пациента (по дате из БД клиентов) бот отправляет поздравление с **подарочным сертификатом** (сумма настраивается, по умолчанию 1000 ₽) и кнопкой «🎁 Использовать сертификат» — переход к администратору.

### Шаг 7. Если сообщение не доставлено
Если пациент заблокировал бота или ещё не нажал `/start`, факт недоставки фиксируется в лист **«Не доставлено»** с указанием типа (`appointment`, `3m`, `6m`, `birthday`, `broadcast`) и причины.

## 3. Фишки для клиники (админская часть)

### 3.1. Админ-редактор контента — `/offers_admin`
Прямо из Telegram администратор клиники может менять, **не трогая код**:
- стартовый текст приветствия;
- стартовое фото;
- заголовок блока акций;
- добавлять / редактировать / удалять акции (текст, фото, кнопки-ссылки);
- предпросматривать стартовый экран и меню акций перед публикацией.

### 3.2. Кастомные рассылки — `/broadcast`
Пошаговый мастер:
1. Загружаете фото (или «пропустить»).
2. Вводите текст.
3. Добавляете кнопки (или без них).
4. Выбираете получателей: `all` (все, кто нажал `/start`) или список `@username` через пробел/запятую.
5. Подтверждаете отправку.

Рассылка уважает ограничения Telegram: писать можно только тем, кто уже запускал бота. Недоставленные автоматически уходят в лист «Не доставлено».

### 3.3. Управление админами — через Google Sheets
Список администраторов ведётся в листе **«Список админов»** (колонка `A` — `@username`). Добавили строчку — человек получил доступ к админ-командам. Никакого деплоя.

### 3.4. Интеграция с Google Sheets (единая точка правды)
Таблица используется и как источник данных, и как журнал событий:

| Лист | Назначение |
|---|---|
| **Записи для бота** | Расписание напоминаний: запись на завтра (A–D), 3 мес. (E–G), 6 мес. (J–L). Если E/F или J/K не заполнены — бот берёт A/B автоматически. |
| **БД - клиенты** | `tg_username`, ФИО, телефон, `tg_user_id`, дата рождения, время согласия. Синхронизируется при старте и после регистрации. |
| **Не готов записаться (комментарии)** | Все отказы с комментариями клиента. |
| **Не доставлено** | Лог недоставленных сообщений (тип + причина). |
| **Список админов** | Управление доступом. |

### 3.5. Статусы в таблице (автозаполнение ботом)
- `C` — статус по записи на завтра (подтвердил / отменил / не готов / напомнить через 2 недели).
- `D` — причина отмены записи.
- `G` — статус по 3-месячному напоминанию.
- `L` — статус по 6-месячному напоминанию.

### 3.6. Тестовые команды для админов
- `/test_main` — посмотреть, как выглядит основное сообщение.
- `/test_daily [today|tomorrow|N]` — прогнать ежедневную рассылку вручную для отладки.
- `/test_daily_debug` — диагностика: сколько строк, сколько кандидатов, что ушло.
- `/test_birthday` — проверка поздравлений.
- `/test_reset` — сбросить своё состояние для повторного прохождения сценария.
- `/whoami` — проверить, видит ли бот тебя как админа.

## 4. Технически (кратко)

- **Язык:** Python 3, `python-telegram-bot`, `FastAPI` (для режима webhook), `APScheduler` (расписание), `gspread` (Google Sheets), `SQLite` (локальное состояние пользователей и очередь недоставленных событий).
- **Деплой:** Docker + docker-compose. Один контейнер с ботом, опционально nginx для webhook. Разворачивается на любом Ubuntu-сервере.
- **Два режима работы:**
  - **Polling** (по умолчанию) — не требует домена и SSL, бот сам опрашивает Telegram.
  - **Webhook** — при наличии https-домена, Telegram сам отправляет события боту.
- **Часовой пояс:** настраивается, по умолчанию `Asia/Novosibirsk`. Ежедневная рассылка в 12:00.
- **Резервирование:** локальная SQLite-база хранит согласия, подписки, очередь недоставок — при падении связи с Google события не теряются и доотправляются при восстановлении.
- **CI:** GitHub Actions прогоняет `ruff` (линтер) и `pytest` (тесты) на каждый коммит. Покрыты тестами: расписание, Google Sheets клиент, хранилище, хендлеры бота.

---

## 5. Ценность для клиники в одну строку

Бот закрывает три больные точки стоматологии: **возврат пациентов** (напоминания 3/6 месяцев + поздравления), **снижение пропусков** (подтверждение за день + управление отменами), **лёгкие продажи абонементов и акций** (редактируемое меню спецпредложений + рассылки).
